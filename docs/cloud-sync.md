# S3 加密云同步

「设置 → 云同步」支持手动上传与下载主机保险库。同步主机、嵌套分组、凭据、跳板与代理配置、已保存的主机密码、密码凭据的密码、代理密码、凭据私钥文件与口令。SSH Agent 凭据仅同步配置；Agent、硬件密钥及自动查找的 `~/.ssh` 私钥仍由各设备自行配置。

## 配置与首次上传

1. 填写区域、存储桶、对象路径、访问密钥 ID 和访问密钥。
2. AWS S3 的端点可以留空。其他服务填写 HTTPS 端点；默认使用路径寻址。按服务要求选择「使用虚拟主机寻址」，该模式的自定义端点应包含桶名。
3. 临时凭据还需填写临时令牌。访问密钥和令牌保存在系统钥匙串，再次打开时输入框为空；留空保留已保存的值。「清除临时令牌」用于移除旧令牌。
4. 点击「保存配置」，输入至少 12 个字符的主密码，点击「上传本地保险库」。
5. 创建完成后点击「复制恢复密钥」，将密钥离线保存。创建设备的系统钥匙串也会保留恢复密钥，便于请求响应丢失后找回。

使用 AWS Signature V4。账号需要保险库对象的 `s3:GetObject` 和 `s3:PutObject` 权限，不需要列桶权限。S3 服务必须正确实现 `If-None-Match`、`If-Match` 条件写入并返回 ETag。建议启用桶版本控制；客户端会拒绝自动重建已经同步后被删除的对象。

## 在另一台设备使用

保存相同的 S3 配置，输入原主密码或恢复密钥，点击「下载并预览」。预览显示云端与本地的主机、分组和凭据数量及本地加密备份位置。关闭远程终端与 SFTP 标签，停止端口转发，点击「应用此保险库…」并确认替换。

应用是整个清单替换：云端缺失的本地主机和分组会被删除，相应书签、转发规则和限定命令片段也会删除。仍存在的项按稳定标识匹配，保留本地数字 ID；现存主机的书签、转发规则、最近连接记录和系统标记留在本机。私钥写入本机私钥目录，密码与口令写入系统钥匙串。

临时连接、运行状态、SFTP 传输、界面设置、主机信任记录和命令历史不参与同步。

## 冲突与备份恢复

上传前比较上次成功同步的 ETag，并使用条件写入。云端变化或首次连接已有保险库时，上传停止，保存双方的加密冲突副本。下载预览后选择：

- **应用此保险库…**：使用云端内容替换本地。
- **保留本地并上传…**：确认后使用本地内容替换预览的云端版本。云端再次变化时上传失败，需要重新下载预览。
- **锁定 / 取消预览**：保留双方现状。

加密副本保存在 `<数据目录>/cloud-sync/backups/`。填写相应主密码或恢复密钥后，点击「导入加密备份…」可以离线预览并恢复。备份保留到用户自行清理；导入创建新私钥文件，先前托管的私钥文件和不再使用的钥匙串条目也暂时保留。用户自己引用的私钥文件不会被覆盖或删除。

本地清单或凭据在预览后变化时导入中止。钥匙串或数据库失败时尝试恢复旧值，不推进同步游标；补偿失败时提示使用应用前的备份。异常退出也可以从备份恢复。

## 加密与限制

- 随机 256 位数据密钥，XChaCha20-Poly1305 加密并认证内容与密钥封套。
- 主密码通过 Argon2id 派生包装密钥：64 MiB 内存、3 次迭代、4 路并行、随机 128 位盐。参数由格式版本固定。
- 独立恢复密钥包装同一数据密钥。主密码和恢复密钥不上传；关闭设置或锁定时清除解锁输入与预览。
- 上传已有保险库不会修改主密码。第一版未提供主密码修改、设备撤销、后台自动同步、按记录合并或团队共享。
- 云端仍能看到对象大小、访问时间和账号。首次接入设备没有独立历史信任基准；已同步设备检查保险库身份与版本回退。加密不能防止对象删除。
- 主密码、恢复密钥及创建设备的钥匙串副本全部丢失后，保险库无法解密。

参考：[S3 条件写入](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)、[Argon2 标准](https://www.rfc-editor.org/rfc/rfc9106.html)、[RustCrypto XChaCha20-Poly1305](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/)。
